# Claude Code (CLI)

**SSE:** поддерживается напрямую, мост не нужен.

## Способ 1 (рекомендуемый) — одна команда в терминале

Конфиг править не нужно, Claude Code запишет всё сам.

Без токена (`MCP_AUTH_TOKEN` в `.env` пустой):

```bash
claude mcp add --transport sse ozon http://localhost:8000/sse
```

С токеном:

```bash
claude mcp add --transport sse ozon http://localhost:8000/sse \
  --header "Authorization: Bearer <MCP_AUTH_TOKEN>"
```

Сервер на другой машине — подставьте её адрес: `http://192.168.1.50:8000/sse`.

### Скоуп: где сервер будет виден

Флаг `--scope` (сокращённо `-s`) определяет, из каких проектов вы увидите `ozon`:

| Скоуп | Флаг | Где записывается | Кто видит |
|-------|------|------------------|-----------|
| Локальный (по умолчанию) | `-s local` | `~/.claude.json`, в секции текущего проекта | только вы и только в этом каталоге |
| Пользовательский | `-s user` | `~/.claude.json`, глобально | вы во всех своих проектах |
| Проектный | `-s project` | `.mcp.json` в корне проекта | все, кто клонирует репозиторий |

Практически: если сервер нужен вам везде — берите `-s user`, иначе в соседнем
проекте инструментов `ozon_*` не будет и вы решите, что подключение слетело.

```bash
claude mcp add --transport sse --scope user ozon http://localhost:8000/sse
```

### Проверить, что получилось

```bash
claude mcp list
```

В списке должна быть строка вида `ozon: http://localhost:8000/sse (SSE) - ✓ Connected`.
`✗ Failed to connect` означает, что сервер не поднят, не тот адрес или не принят
токен. Подробнее по одному серверу — `claude mcp get ozon`, там же строка `Issue:`
с причиной ошибки.

Внутри сессии — слэш-команда `/mcp`: статус `connected` и число инструментов
(должно быть 151). Дальше просто спросите: «покажи список магазинов Ozon» —
Claude вызовет `ozon_list_shops`.

Удалить: `claude mcp remove ozon` (с тем же `--scope`, если он был не локальный).

## Способ 2 — правка конфига руками

Нужен, если конфигурацию хочется положить в репозиторий проекта, чтобы у всей
команды сервер подключался сам.

| ОС | Пользовательский / локальный скоуп | Проектный скоуп |
|----|-----------------------------------|-----------------|
| macOS | `~/.claude.json` | `.mcp.json` в корне проекта |
| Linux | `~/.claude.json` | `.mcp.json` в корне проекта |
| Windows | `%USERPROFILE%\.claude.json` | `.mcp.json` в корне проекта |

Графического интерфейса нет — внутри сессии есть слэш-команда `/mcp`.

`.mcp.json` в корне проекта (или соответствующая секция `~/.claude.json`):

```json
{
  "mcpServers": {
    "ozon": {
      "type": "sse",
      "url": "http://localhost:8000/sse",
      "headers": {
        "Authorization": "Bearer ${OZON_MCP_TOKEN}"
      }
    }
  }
}
```

Подстановка переменных окружения (`${VAR}`, `${VAR:-default}`) в `.mcp.json`
поддерживается для полей `url`, `headers`, `command`, `args`, `env` — так токен
не попадёт в git. Без токена блок `headers` просто убирается.

## Оговорки

- Запись с `url`, но без `type` Claude Code считает stdio-сервером и ругается:
  `has a "url" but no "type"`. Для нашего эндпоинта — всегда `"type": "sse"`.
- Если токен неверный, Claude Code помечает соединение как failed и **не**
  переходит на OAuth-флоу.
- Пробелы и переносы строк в значении заголовка не обрезаются — Claude Code
  предупреждает `Leading or trailing whitespace in: headers.Authorization`.
- Серверы из проектного `.mcp.json` требуют интерактивного подтверждения при
  первом запуске (`claude mcp reset-project-choices` — сбросить решение).
- Транспорт SSE в спецификации MCP помечен как устаревший в пользу Streamable
  HTTP; Claude Code его по-прежнему поддерживает, но пишет об этом в документации.
